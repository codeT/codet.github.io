## 摘要

LLM 驱动的自动化渗透测试智能体，通常只针对**既不检测也不响应攻击的静态靶标**进行评测，因此它们在智能防御下的真实表现从未被验证。多步攻击链的因果一致性同样依赖不稳定的 LLM 推理，而智能体的决策对人类分析师而言又是不透明的。这三个短板——**真实性、一致性、可审计性**——通常被孤立地修补。

我们提出 **ZERO-APT**：一个回合制的「攻击者-防御者-裁判」框架，在单一架构内同时解决这三者。
- **真实性**：内置一个可配置的 LLM 防御者，消费 Sysmon 遥测并实时检测攻击，使攻击者面对的是一个活的对手而非被动靶标。
- **一致性**：用三种架构机制把因果一致性从不稳定的 LLM 推理中「搬」进受约束的系统架构——规划与执行分离、多维 ReAct 反馈、硬约束过滤的动作库。
- **可审计性**：一个专职的裁判智能体逐回合裁决、维护全局状态，并产出结构化的事后 CTI（网络威胁情报）报告，使每个决策都可追溯。

我们在 Windows Server 2022 后渗透原型上、用三种防御者配置、跨五个场景评测。ZERO-APT 取得 **79% 攻击成功率**（Aurora 22%、PentestGPT 39%）、**因果一致性得分 0.860**（Aurora 0.930、Claude Code 0.520），并通过结构化 CTI 报告实现端到端决策可审计。

## 1. 引言：三大挑战

渗透测试长期依赖人工、难以规模化。LLM 正在快速重塑这一领域，而自动化渗透测试是其中演进最快的子方向之一。已有工作分三条路线：(1) 把 LLM 当辅助、用 PDDL/MCTS 强制形式可行性；(2) 把渗透建模为马尔可夫决策过程、用海量模拟交互训练攻击策略（RL）；(3) 把 LLM 置于决策中心。本文走第三条路线，但指出横亘在「以 LLM 为核心」与「可部署系统」之间的三大挑战：

1. **真实性（Realism）**：现有攻击者几乎都在不检测、不响应、不反击的静态靶标上测试，与真实对抗环境相去甚远——真实环境中每个动作都会留下可检测痕迹，防御者会实时调整。据我们所知，尚无公开基准把「可配置的 LLM 防御者」纳入评测基础设施。
2. **一致性（Consistency）**：多步渗透要求每一步的前置条件由先前步骤产生，但 LLM 在长程上不稳定——幻觉、上下文遗忘、逻辑漂移会反复「折断」攻击链。现有补救要么把 LLM 限制在单场景利用，要么用经典规划/RL 替换其决策，都无法在对抗压力下泛化到多步后渗透，且无人在**架构层面**正面解决。
3. **可审计性（Auditability）**：LLM 的内部思维链对外部分析师不透明，且近期研究表明这些解释常常「不忠实」——模型给出看似合理、却掩盖真实决策动因的推理。没有可审计的决策，攻击成功就无法被系统地理解、复现或泛化。

## 2. 相关工作与动机

三条研究路线各自押注「智能应当驻留在何处」：
- **经典规划 + LLM 辅助**：把 PDDL/MCTS 放在推理核心，攻击链对已知目标一次性预计算并下发，运行中防御者告警无法触发重规划——是自动化，而非自主。
- **强化学习（RL）**：把渗透建模为 MDP，靠海量模拟训练策略。反复出现的瓶颈是**环境过拟合**：面对陌生环境或智能防御者时策略退化，因为 RL 价值函数无法在语义层面把握对手意图。
- **LLM 作为规划核心**：能力随模型能力本身演进，但「智能体能力的边界一直是模型能力的边界」，架构也只围绕「榨干单个模型」组织。

很少有人追问：在带智能防御的真实对抗环境中，**因果一致性与决策可审计性能否由架构保证，而不是交给 LLM 推理质量**？ZERO-APT 正是把架构焦点从「扩展 LLM 能力」转向「在攻防回路内提供结构性保证」。

下表对比三个代表系统在三个维度上的能力（✓=具备，✗=不具备，◐=部分）：

| 系统 | 真实性 | 一致性 | 可审计性 |
|------|:------:|:------:|:--------:|
| PentestGPT | ✗ | ✗ | ✗ |
| Aurora | ✗ | ✓ | ✗ |
| Claude Code | ◐ | ✗ | ◐ |
| **ZERO-APT** | ✓ | ✓ | ✓ |

三个缺口彼此纠缠、并非独立：没有真实性，评测就没有对抗压力；没有一致性，加入防御只会放大因果断裂；没有可审计性，成功的攻击无法被理解或复现。孤立修补任一缺口都行不通。ZERO-APT 因此在单一回路内同时闭合三者。

## 3. 系统设计

ZERO-APT 以回合制运行「攻击者 → 防御者 → 裁判」：攻击者执行动作，防御者检查系统日志，裁判裁决本回合并更新全局状态，进而驱动下一回合策略。直到达成任务目标或到达逐场景回合上限（S1=8, S2=10, S3=12, S4=12, S5=9）。三方共享结构化全局状态，但每方只读取其被授权访问的切片。

### 3.1 防御者（Defender）

ZERO-APT 把 LLM 防御者作为一等系统组件，运行三阶段检测流水线：Monitor 先从 ELK Stack 拉取 1 分钟滑动窗口内的 Sysmon 事件并格式化；L2/L3 下再用四条 Sysmon 签名规则（Event ID 1/3/11/12–14）匹配；最后把标注后的事件喂给 Monitor LLM，输出入侵判定、MITRE ATT&CK 技术 ID、置信度（0–100）、证据摘要与攻击意图研判。**防御者只通过全局状态读取系统日志，永远看不到攻击者的内部计划或命令序列**，与真实防御一致。

防御者强度沿两个正交维度定义——日志中是否混入正常活动噪声、是否向 Monitor LLM 注入攻击者威胁情报——交叉得到三档递进强度：

| | 无威胁情报 | 有威胁情报 |
|------|:----------:|:----------:|
| 含噪声 | L1（低） | — |
| 干净日志 | L2（中） | L3（高） |

- **L1**：安全薄弱环境，无签名规则、日志带噪、纯 LLM 推理。
- **L2**：常规企业 SOC，四条签名规则提供检测信号 + Monitor LLM 上下文推理与误报抑制。
- **L3**：在 L2 之上叠加「已知对手」态势，注入攻击者 TTP 情报与累积检测历史。

其效果表现为 ASR 单调下降：L1 > L2 > L3。

### 3.2 攻击者（Attacker）：把一致性搬进架构

ZERO-APT 用三种架构机制把「保证因果一致性」的负担从 LLM 卸到系统本身：

**(1) 规划-执行分离**，分配给三个职责不同的 LLM 组件：
- **Planner（规划器）**：持有全局视图，输入任务目标、当前环境知识、裁判反馈与回溯请求，输出高层计划与当前子目标；处理两类回溯（被动/主动）。
- **Dispatcher（调度器）**：两阶段。阶段 1 从动作库检索候选动作、剔除裁判禁用清单、若无剩余则触发回溯；阶段 2 读取命令模板/参数/前后置条件，针对当前环境排序、识别需运行时探索的参数、产出可执行命令序列。
- **Executor（执行器）**：在内部 ReAct 循环中逐步执行迷你计划，每步设重试上限；命令经 WinRM 远程在目标 Windows 主机运行，支持横向移动的跨主机凭据切换。

**(2) 多维 ReAct 反馈**：把 ReAct 从「单个智能体内的推理-动作环」扩展为两个并发层——
- **智能体间反馈**（攻击者-裁判-攻击者闭环）：一旦防御者检测且裁判判防御方胜，Planner 在下一回合收到裁决（含检测依据与判决理由）并据此修订攻击路径。
- **智能体内反馈**（Executor 自调试环）：单条命令失败时，Executor 检查错误输出、调参重试；到达重试上限则跳过当前步而非阻塞全程。

**(3) 硬约束过滤的动作库**：库中含 **775 个后渗透动作**（提炼自 Atomic Red Team），每个声明显式前/后置条件。借鉴 Aurora 的 AALM，**硬条件**（权限等级、工具依赖、所需端口）由 Dispatcher 通过表查找机械匹配，无需 PDDL 规划器；**软条件**（文件路径、账户名、配置值）由 Executor 运行时探索获取。硬条件默认为真，Executor 每回合探测真实状态并把未满足条件翻为假，下一回合 Dispatcher 即排除依赖它的动作——过滤随探索而收紧，动作空间收敛到可行集。

动作的六元组结构：

| 属性 | 类型 | 说明 |
|------|------|------|
| Action ID | string | 唯一 ID，映射 MITRE ATT&CK 技术（Txxxx） |
| Platform | string | 目标平台（Windows/Linux） |
| Executor | string | 执行环境（PowerShell/CMD） |
| Preconditions | object | 硬条件：最低权限、工具依赖、网络端口 |
| Postconditions | object | 效果：创建的文件、进程、凭据类型 |
| Command Template | string | 参数化，参数由 Executor 运行时填充 |

**两类回溯**：被动回溯（跨回合、裁判驱动）——裁判因环境约束或检测判本回合失败，Planner 下一回合读取观察并改路；主动回溯（同回合、Dispatcher 驱动）——Dispatcher 找不到满足前置条件的动作时回溯到 Planner 改子目标（每回合上限 3 次）。

### 3.3 裁判（Judge）

裁判逐回合在线裁决并维护全局状态，承担两项职责：

**逐回合裁决**：裁判 LLM 同时接收攻击者完整回合反馈与防御者结构化检测输出，按其与攻击者实际行为的对应度与逻辑充分性，对防御方证据质量打 0–100 分，**阈值 75**。无论结果如何，裁判输出自然语言裁决——这是防御侧信息到达攻击者的**唯一通道**：攻击者胜则指出防御盲点，防御者胜则记录检测证据与归因供 Planner 规避。

| 条件 | 判定 | 对攻击者的后果 | 状态更新 |
|------|------|----------------|----------|
| 证据分 ≥ 75 | 防御方胜 | 本回合攻击结果不被承认 | 被封动作加入禁用清单 |
| 证据分 < 75 | 攻击方胜 | 攻击结果写入状态 | 发现的文件/凭据等进入知识库 |

**事后 CTI 报告**：实验终止后离线执行，产出两层结构化报告——历史层（攻击概览、逐回合时间线、禁用动作演化）与分析层（防御压力下的攻击者策略评估、防御者系统性盲点定位、防御建议）。攻击者推理链、防御者检测逻辑、裁判裁决依据、回溯触发原因均被结构化记录，给分析师一条完全可追溯的决策链。

## 4. 实验评测

共进行 **1,400 次实验**（5 场景 × 4 方案 × 3 防御强度 × 20 次重复 = 1,200，外加 5 场景 × 2 消融变体 × 20 次 = 200）。所有 LLM 模块使用 Claude Opus 4.7。

**四个核心指标**（其余辅助指标见原文附录）：

<div class="formula">\[ \mathrm{ASR} = N_{\text{success}} \,/\, N_{\text{total}} \]</div>

<div class="formula">\[ \mathrm{CCS} = \overline{\text{expert scores}} \,/\, 10 \quad (\text{ICC}=0.84) \]</div>

<div class="formula">\[ \mathrm{CBF\%} = N_{\text{failed}} \,/\, N_{\text{total commands}} \]</div>

<div class="formula">\[ \mathrm{BSR} = N_{\text{recovered}} \,/\, N_{\text{total backtracks}} \]</div>

其中 CCS（因果一致性得分）由两名安全专家独立复核每次实验的完整攻击链，从 10 分起每发现一处因果不一致扣 1 分，平均后归一化到 [0,1]；CBF%（因果断裂失败率）从反面度量因果断裂是否转化为执行失败。

### 4.1 真实性验证：防御压力是真实的

四个方案 × 五场景 × 三档防御强度的聚合 ASR 呈**单调 L1 > L2 > L3 下降**（Friedman χ² = 8.40, p = 0.015），说明防御升级施加了系统性、可测量的压力。**ZERO-APT 衰减最慢**（94% → 77% → 52%），且与基线的差距在防御最强处最大：

| 方案 | L1（弱） | L2（标准） | L3（强） |
|------|:-------:|:---------:|:-------:|
| **ZERO-APT** | 94% | 77% | 52% |
| Claude Code | 94% | 63% | 37% |
| Aurora | 84% | 20% | 0% |
| PentestGPT | 70% | 41% | 12% |

Aurora 的失效最具诊断意义：PDDL 在规划期就锁死所有路径，环境一动，「一次性烤进去」的因果正确性反而成了负债——L3 全 TTP 情报下全场景归零。Claude Code 在 L1 与 ZERO-APT 持平（均 94%），但 L2/L3 因缺少结构化回溯与硬约束过滤而分别落后 14pp、15pp。「L1 持平、L2/L3 分化」也排除了「更强基座模型」或「基准偏置」的解释——所有方案共用 Claude Opus 4.7。

### 4.2 一致性验证

Aurora 的 CCS（0.930）最高——PDDL 形式约束几乎不留因果不一致；但其 22% 的 ASR 说明**因果正确是必要而非充分**：链路因果正确，却在第一次自适应需求面前死掉。**ZERO-APT 是唯一同时落在「高 CCS + 高 ASR」区域的系统**（CCS 0.860，ASR 79%；vs PentestGPT/Claude Code 均 p < 0.001）。CBF% 从反面印证：ZERO-APT 10.3%，远低于 Claude Code（27.4%）与 PentestGPT（38.6%）。

**架构消融**（n=100）显示两个机制各自不可或缺：

| 变体 | ASR | CCS | CBF% | BSR | 回合 |
|------|:---:|:---:|:----:|:---:|:----:|
| **ZERO-APT（完整）** | 79% | 0.860 | 10.3% | 0.661 | 3.96 |
| −ActionLib（去动作库） | 48% | 0.510 | 29.9% | 0.310 | 5.18 |
| −MultiReAct（退化为单层 ReAct） | 42% | 0.420 | 28.5% | 0.188 | 6.22 |

结论：在对抗压力下，「知道何时切换策略」（Planner 借裁判反馈回溯）比「知道有哪些策略可用」（动作库）更关键。

### 4.3 可审计性：一个案例

一份成功 S2（持久化 + 提权，ASR=1, CCS=0.91, 四回合）的 CTI 报告片段，把审计轨迹与两类回溯具象化：
- **R1 硬约束降级**：写 `HKLM\...\Run` 因 `ERROR_ACCESS_DENIED` 失败，Executor 同回合参数重试回退到 `HKCU`；防御者标记注册表修改（T1547.001, EID 13），裁判判防御方胜，但侦察发现被刻意保留以维持跨回合信息连续性。
- **R2 被动回溯（裁判驱动）**：Planner 读取 R1 观察，切到计划任务（T1053.005），因两技术在动作库 DAG 中共享「可写用户级持久化位置」前置条件，切换零成本，`schtasks /create` 未被检测地成功。
- **R3→R4 战术切换**：经 `cmstp.exe` 的 UAC 绕过（T1548.002）被异常父子进程检测拦截；Planner 判定所有 LOLBin 变体检测概率 >80%，直接切到令牌操纵（T1134.002，动作库元数据标记为 Sysmon 事件最少的动作），经命名管道模拟提权到 SYSTEM。

对 50 份 CTI 报告由两名专家独立评估，ICC(A,1)=0.81、层级一致率 88%，表明裁判的审计达到可用参考标准。

## 5. 讨论与结论

- **防御者范围**：当前防御者止于基于 Sysmon 的检测、无主动响应；「智能防御」取前瞻含义。叠加 Cloak/Honey/Trap 等欺骗或多智能体防御协同，可构成更丰富的未来形态。
- **残留 LLM 依赖**：系统强制因果一致性，但 Planner 推理与 Judge 证据打分仍依赖 LLM——架构是**约束**而非**替代** LLM，缩小了出错面而非消除它。
- **可移植性**：把 ZERO-APT 剥到只剩攻击者并在 5 台 HackTheBox 机器上运行，其表现与其他多智能体渗透工具相当，正符合「增益来自架构而非 LLM」的预期。

**结论**：在真实智能防御下，仅靠扩大 LLM 规模无法弥合真实性、因果一致性与可审计性这三道缺口；**架构层面的机制可以**。ZERO-APT 用攻击者-防御者-裁判闭环，把因果一致性从不可靠的 LLM 推理中提出，并以独立裁判实现端到端可审计；其架构优势随防御强度增大而扩大，消融实验把增益归因于架构而非原始 LLM 能力。作者开源了代码与场景配置，作为攻防协同演化的基准。

## Abstract

LLM-driven automated penetration testing agents are typically evaluated against **static targets that neither detect nor respond to attacks**, so their behavior under intelligent defense remains untested. The causal consistency of multi-step attack chains likewise hinges on unstable LLM reasoning, and agent decisions remain opaque to human analysts. These three shortcomings — in **realism, consistency, and auditability** — are usually patched in isolation.

We present **ZERO-APT**, a turn-based attacker-defender-judge framework that addresses them within a single architecture.
- **Realism**: a configurable LLM Defender consumes Sysmon telemetry and detects attacks in real time, exposing the attacker to a live opponent rather than a passive target.
- **Consistency**: three architectural mechanisms move causal consistency from unstable LLM reasoning into enforced system architecture — separation of planning from execution, multi-dimensional ReAct feedback, and a hard-constraint-filtered action library.
- **Auditability**: a dedicated Judge agent adjudicates each round, maintains global state, and emits structured post-hoc CTI reports that make every decision traceable.

On a Windows Server 2022 post-exploitation prototype across five scenarios with three Defender configurations, ZERO-APT reaches **79% attack success rate** (Aurora 22%, PentestGPT 39%), a **Causal Consistency Score of 0.860** (Aurora 0.930, Claude Code 0.520), and end-to-end decision auditability.

## 1. Introduction: Three Challenges

Penetration testing has long rested on manual expertise and remained hard to scale. LLMs are reshaping it fast, and automated penetration testing is among the fastest-moving sub-areas. Three lines of work organize the space: (1) LLM-as-auxiliary with PDDL/MCTS for formal feasibility; (2) penetration as an MDP trained via massive simulation (RL); (3) LLM at the center of decision-making. We pursue the third line, but three challenges stand between this premise and a deployable system:

1. **Realism.** Existing attackers are almost always benchmarked against static targets that do not detect, respond, or counterattack. To our knowledge, no published benchmark embeds a configurable LLM Defender as part of its evaluation infrastructure.
2. **Consistency.** Multi-step penetration requires each step's preconditions to be produced by earlier steps, yet LLMs are unstable over long horizons: hallucination, context forgetting, and logical drift repeatedly snap the chain. Existing remedies neither generalize to multi-step post-exploitation under adversarial pressure nor confront the issue at the architectural level.
3. **Auditability.** An LLM's internal chain of thought is opaque to analysts, and recent work shows these explanations are often unfaithful. Without auditable decisions, successes cannot be systematically understood, reproduced, or generalized.

## 2. Related Work & Motivation

Each line makes a distinct architectural bet on where intelligence should reside:
- **Classical planning + LLM assistance**: PDDL/MCTS at the core; attack chains are precomputed against a known target and dispatched in one shot, so a mid-run alert cannot trigger replanning — automation, not autonomy.
- **Reinforcement learning**: penetration as an MDP trained via massive simulation. The recurring bottleneck is **environmental overfitting**: policies degrade against unfamiliar environments or intelligent defenders, because RL value functions do not grasp opponent intent semantically.
- **LLM as planning core**: tracks LLM capability itself; the boundary of agent capability has so far been the boundary of model capability.

A different question rarely surfaces: under intelligent defense, **can causal consistency and decision auditability be guaranteed by the architecture rather than left to LLM reasoning quality?** ZERO-APT shifts the focus from extending LLM capability to providing structural guarantees inside an attacker-defender loop.

| System | Realism | Consistency | Auditability |
|--------|:-------:|:-----------:|:------------:|
| PentestGPT | ✗ | ✗ | ✗ |
| Aurora | ✗ | ✓ | ✗ |
| Claude Code | ◐ | ✗ | ◐ |
| **ZERO-APT** | ✓ | ✓ | ✓ |

The three gaps are entangled, not independent: without realism, evaluation exerts no adversarial pressure; without consistency, adding defense only widens causal breaks; without auditability, successes cannot be understood or reproduced. ZERO-APT closes all three at once inside a single loop.

## 3. System Design

ZERO-APT runs a turn-based loop **Attacker → Defender → Judge**: the Attacker performs an action, the Defender inspects system logs, the Judge adjudicates the round and updates global state, which drives the next round. It continues until the goal is met or the per-scenario round limit (S1=8, S2=10, S3=12, S4=12, S5=9) is reached. The three agents share a structured global state, but each reads only the slice it is authorized to access.

### 3.1 Defender

ZERO-APT embeds an LLM Defender as a first-class component running a three-stage pipeline: the Monitor pulls Sysmon events from the ELK Stack within a 1-minute sliding window; under L2/L3 they are matched against four Sysmon signature rules (Event IDs 1/3/11/12–14); finally the annotated events feed the Monitor LLM, which emits an intrusion judgment, a MITRE ATT&CK technique ID, a confidence score (0–100), an evidence summary, and an attack-intent rationale. **The Defender reads only system logs, never the Attacker's internal plans or commands**, mirroring real defense.

Defender intensity is defined along two orthogonal dimensions — whether normal-activity noise is mixed into logs, and whether attacker threat intelligence is injected — yielding three tiers:

| | No Threat Intel. | With Threat Intel. |
|------|:----------------:|:------------------:|
| With noise | L1 (Low) | — |
| Clean logs | L2 (Medium) | L3 (High) |

- **L1**: security-weak environment, no signature rules, noisy logs, pure LLM reasoning.
- **L2**: routine enterprise SOC, four signature rules + Monitor LLM contextual reasoning and false-positive suppression.
- **L3**: layers a known-adversary posture on L2, injecting attacker TTP intelligence and accumulated detection history.

The effect surfaces as a monotonic ASR decline, L1 > L2 > L3.

### 3.2 Attacker: Lifting Consistency into Architecture

Three architectural mechanisms move the burden of causal consistency off the LLM and onto the system:

**(1) Planning-execution separation**, across three LLM components:
- **Planner**: holds the global view; inputs mission goals, environment knowledge, Judge feedback, and backtrack requests; emits a high-level plan and current subgoal; handles passive/active backtracking.
- **Dispatcher**: Phase 1 retrieves candidate actions, drops forbidden ones, backtracks if none remain; Phase 2 reads command templates / parameters / pre-postconditions, sequences against the environment, and emits the executable command sequence.
- **Executor**: runs the mini-plan step-by-step in an internal ReAct loop with per-step retry caps; commands run remotely via WinRM, with cross-host credential switching for lateral movement.

**(2) Multi-dimensional ReAct feedback**, two concurrent layers:
- **Inter-agent** (attacker-judge-attacker closure): when the Defender detects and the Judge rules for the Defender, the Planner receives the adjudication next round and revises the path.
- **Intra-agent** (Executor self-debugging): on command failure, the Executor inspects errors, adjusts parameters, retries; on hitting the cap, it skips the step rather than blocking the run.

**(3) Hard-constraint-filtered action library**: **775 post-exploitation actions** distilled from Atomic Red Team, each declaring explicit pre/post-conditions. Building on Aurora's AALM, **hard conditions** (privilege, tool deps, ports) are matched mechanically via Dispatcher table lookups (no PDDL planner); **soft conditions** (paths, account names, configs) are gathered by the Executor at runtime. Hard conditions default to true; the Executor flips unmet ones to false, and the next round's Dispatcher excludes dependent actions — so the action space converges to the feasible set.

| Attribute | Type | Description |
|-----------|------|-------------|
| Action ID | string | Unique ID mapping to MITRE ATT&CK technique (Txxxx) |
| Platform | string | Target platform (Windows/Linux) |
| Executor | string | Execution environment (PowerShell/CMD) |
| Preconditions | object | Hard: min. privilege, tool deps, ports |
| Postconditions | object | Effects: created files, processes, credential types |
| Command Template | string | Parameterized; filled by Executor at runtime |

**Two backtrack paths**: passive (cross-round, Judge-driven) and active (same-round, Dispatcher-driven, capped at three attempts per round).

### 3.3 Judge

The Judge adjudicates online each round and maintains global state, with two duties:

**Per-round adjudication**: the Judge LLM receives the Attacker's full round feedback and the Defender's structured detection output, scores the Defender's evidence quality on 0–100, with a **threshold of 75**. Its natural-language ruling is the **sole channel** through which defense-side information reaches the Attacker.

| Condition | Verdict | Consequence for Attacker | State Update |
|-----------|---------|--------------------------|--------------|
| evidence score ≥ 75 | Defender wins | Round's results not recognized | Blocked actions → forbidden list |
| evidence score < 75 | Attacker wins | Results written to state | Discovered files/credentials → knowledge base |

**Post-hoc CTI report**: produced offline after termination, in two layers — a historical layer (attack overview, per-round timeline, forbidden-action evolution) and an analytical layer (Attacker strategy under pressure, Defender's systematic blind spots, defensive recommendations) — giving analysts a fully traceable decision chain.

## 4. Evaluation

**1,400 experiments** (5 scenarios × 4 schemes × 3 Defender intensities × 20 reps = 1,200, plus 5 × 2 ablations × 20 = 200). All LLM modules use Claude Opus 4.7.

**Four core metrics:**

<div class="formula">\[ \mathrm{ASR} = N_{\text{success}} \,/\, N_{\text{total}} \]</div>

<div class="formula">\[ \mathrm{CCS} = \overline{\text{expert scores}} \,/\, 10 \quad (\text{ICC}=0.84) \]</div>

<div class="formula">\[ \mathrm{CBF\%} = N_{\text{failed}} \,/\, N_{\text{total commands}} \]</div>

<div class="formula">\[ \mathrm{BSR} = N_{\text{recovered}} \,/\, N_{\text{total backtracks}} \]</div>

CCS is scored by two independent experts (start at 10, −1 per causal inconsistency, normalized to [0,1]); CBF% measures, from the negative side, whether causal breaks translate into execution failures.

### 4.1 Realism Validation

Aggregated ASR shows a **monotonic L1 > L2 > L3 decline** (Friedman χ² = 8.40, p = 0.015). **ZERO-APT decays slowest** (94% → 77% → 52%), with the gap widening exactly where defense bites hardest:

| Aurora | 84% | 20% | 0% |

### 4.3 Auditability: A Case Study

A successful S2 run (Persistence + Privesc, ASR=1, CCS=0.91, 4 rounds) makes the audit trail concrete:
- **R1 hard-constraint downgrade**: a `HKLM\...\Run` write fails with `ERROR_ACCESS_DENIED`; the Executor falls back to `HKCU` in the same round. The Defender flags the registry modification (T1547.001, EID 13) and the Judge rules Blue Win, but recon findings survive — preserving information continuity across rounds.
- **R2 passive backtracking (Judge-driven)**: the Planner reads R1's observation and switches to a scheduled task (T1053.005); since both share a writable user-level persistence precondition in the action-library DAG, switching costs nothing. `schtasks /create` succeeds undetected.
- **R3→R4 tactical switch**: a UAC bypass via `cmstp.exe` (T1548.002) is blocked by anomalous parent-child detection; the Planner judges all LOLBin variants to have >80% detection probability and switches to token manipulation (T1134.002, the fewest-Sysmon-events action), escalating to SYSTEM via named-pipe impersonation.

Across 50 CTI reports independently assessed by two experts, ICC(A,1)=0.81 with 88% layer-level agreement — the Judge's audit reaches a usable reference standard.

## 5. Discussion & Conclusion

- **Defender scope**: the Defender stops at Sysmon-based detection without active response; "intelligent defense" is used in a forward-looking sense. Adding Cloak/Honey/Trap deception or multi-agent defense coordination would enrich future regimes.
- **Residual LLM dependency**: the architecture **constrains** rather than **replaces** the LLM — Planner reasoning and Judge scoring still ride on it — narrowing the error surface without eliminating it.
- **Portability**: stripped to its Attacker on five HackTheBox machines, ZERO-APT tracks other multi-agent tools — exactly as expected if its gains come from architecture rather than the LLM.

**Conclusion**: under live intelligent defense, scaling LLMs alone does not close the realism / consistency / auditability gaps; **architecture-level mechanisms do**. ZERO-APT's attacker-defender-judge loop lifts causal consistency out of unreliable LLM reasoning and delivers end-to-end auditability via an independent Judge; its architectural advantage widens with defense intensity, and ablation traces the gains to architecture rather than raw LLM capability. The authors release the codebase and scenario configurations as a benchmark for attacker-defender co-evolution.
